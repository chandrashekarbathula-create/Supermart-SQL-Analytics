# Supermart SQL Analytics — Data Dictionary

## 1. Purpose

This data dictionary documents the core tables, analytical views, important columns, business keys, and relationships used in the **Supermart SQL Analytics** project.

The project follows a layered approach:

```text
Raw Tables
    ↓
Clean / Validated Tables
    ↓
Analytical Views
    ↓
KPIs / Stored Procedures
    ↓
Business Analysis
```

The main production-ready tables are:

- `customers_clean`
- `products_dedup`
- `sales_dedup`
- `returns_valid`

The main analytical views are:

- `vw_sales_detail`
- `vw_customer_performance`
- `vw_product_performance`
- `vw_returns_analysis`
- `vw_kpi_summary`

---

# 2. Dataset Architecture

The core business relationship can be represented as:

```text
customers_clean
      │
      │ Customer_ID
      ▼
sales_dedup
      │
      ├──────── Product_ID ────────► products_dedup
      │
      │
      │ Order_ID + Order_Line
      ▼
returns_valid
```

`sales_dedup` acts as the central transactional table.

Customer and product tables provide descriptive dimensions, while `returns_valid` provides return/refund information linked to sales transactions.

# 5. `sales_dedup`

## Purpose

`sales_dedup` is the primary cleaned transactional fact table.

It contains validated sales transactions after duplicate business records and data-quality problems have been handled.

### Grain

**One row per Order_ID + Order_Line**

This is important because one order can contain multiple product lines.

For example:

```text
Order_ID     Order_Line
ORD000100    1
ORD000100    2
ORD000100    3
```

represents one order containing three separate sales lines.

### Business Key

The composite business key is:

```text
Order_ID + Order_Line
```

A unique index was created to protect this grain.

### Important Columns

| Column | Description |
|---|---|
| Order_Line | Individual sales-line identifier |
| Order_ID | Business order identifier |
| Order_Date | Date the customer placed the order |
| Ship_Date | Date the order was shipped |
| Ship_Mode | Shipping method |
| Customer_ID | Customer associated with the transaction |
| Product_ID | Product sold |
| Quantity | Number of units sold |
| Sales | Sales/revenue amount |
| Discount | Discount applied |
| Profit | Profit generated by the sales line |

Additional original/raw date fields may also be retained for audit and transformation purposes.

### Important Data Quality Rules

The following rules were checked:

- Duplicate business keys
- Missing Customer_ID
- Missing Product_ID
- Missing Order_ID
- Missing Order_Line
- Non-positive quantity
- Negative sales values
- Invalid dates

Final duplicate validation confirmed:

```text
Duplicate Order_ID + Order_Line combinations = 0
```

### Final Production Row Count

```text
10,000 sales rows
```

### Final Business Metrics

```text

Sales Lines     : 10,000
Units Sold      : 44,932
Total Sales     : 6,966,436.99
Total Profit    : 1,347,352.20
```

# 16. Date Quality

The dataset covers the primary analytical period:

```text
2022-01-01
to
2025-12-31
```

A sales record with a missing `Order_Date` was identified during QA.

Rather than silently assigning an artificial date, time-based analyses exclude records where:

```sql id="c4a4q7"
Order_Date IS NULL
```

when a valid transaction date is required.

This preserves the underlying record while preventing invalid dates from distorting annual and monthly reporting.

# 19. Analytical Layer

The analytical layer was designed so downstream reporting tools do not need to repeatedly recreate complex joins and business logic.

For example, Power BI or another BI tool can connect directly to:

```text
vw_sales_detail
vw_customer_performance
vw_product_performance
vw_returns_analysis
vw_kpi_summary
```

depending on the required level of analysis.

This separates:

**raw data → transformation logic → validated analytical layer → reporting**

and makes the project easier to maintain, validate, and reuse.
